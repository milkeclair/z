# z.completion

Zshの補完でzの関数名を補完し、関数ドキュメントを表示するmodです。

## インストール

`z.install.mod completion`

`job`がなければ、同時に導入します。

## 概要

`z.completion`は、公開された`z.*`関数のZsh補完を登録します。

Language Serverを起動せず、端末側でzの関数を補完したい場合に使います。

## 設定

Zshの補完が利用できる状態になってから`z.completion.enable`を呼び出します。

```zsh
z.completion.enable
```

## 動作

### 関数名の補完

`z.<Tab>`では、`z.arg.`や`z.str.`のようなルートの名前空間を1回ずつ表示します。名前空間を選ぶと末尾のドットを保って空白を挿入せず、その中の補完を続けられます。`z.str.`や`z.str.color.`のような深い接頭辞では、さらに下位のものも含む一致した公開関数をすべて表示します。コマンド位置・引数位置とも候補を1行ずつ並べ、別名と外部コマンドも引き続き候補に含めます。他のコマンドには、以前登録されたコマンド補完を使います。

```zsh
z.arg.na<Tab>
# => z.arg.named
# => z.arg.named.shift
```

### コマンド固有の補完

対象関数の下位に`<関数名>.completion._run`がある場合は、その関数を補完処理として登録します。例えば`z.pj`では登録済みプロジェクト名を補完します。専用の関数がない場合は共通の関数名補完とドキュメント表示を使います。

### ドキュメントの表示

```zsh
z.arg.named <Tab>
# z.arg.namedのドキュメントを表示する
```

引数名はシアン、`REPLY`・`return`・`example`の見出しは黄色、インデントされた使用例は緑で表示します。それ以外の文章は端末の既定色を使います。

関数名の補完を優先します。例えば`z.arg.n<Tab>`では関数の候補を表示し、同じ補完操作ではドキュメントを表示しません。

### コード引数の補完

コメントで`[code]`と指定された引数では、文字列内のコマンドを補完します。名前付き引数、位置引数、可変長引数と、単引用・二重引用・ANSI引用を扱います。コマンド置換の内側と、空白のない区切り直後でも補完できます。

```zsh
z.t.mock name=worker behavior='z.arg.g<Tab>
# 内側のz.arg.getを補完する
```

内側が関数の引数位置なら、その関数のドキュメントを表示します。`[code | 'call_original']`のような許可値も候補に含め、許可値そのものを入力している場合はコードとして解析しません。

型アノテーションと許可値は、引数ヘルプにも表示します。内側の補完にはZsh標準のcompsysを使い、挿入時の引用・エスケープはその方式に従います。入力文字列のコマンドを実行する処理はありません。

## キャッシュ

`z.completion.enable`は関数名のキャッシュを同期的に作成し、ドキュメントと引数仕様のキャッシュを作るバックグラウンドジョブを起動します。

シェルの終了時や補完の再有効化時には、未完了のドキュメントジョブをキャンセルします。完了済みのジョブの結果は、回収できるよう保持します。

キャッシュ用の変数:

- `z_completion_function_names`
  - 補完候補に使う公開z関数の名前
- `z_completion_docs`
  - 関数名をキーとするドキュメント
- `z_completion_cache_ready`
  - ドキュメントのキャッシュを読み込み終えたか
- `z_completion_argument_specs`
  - code型がある関数の引数種別・位置・許可値。TAB時はこのキャッシュから補完対象を判断する
